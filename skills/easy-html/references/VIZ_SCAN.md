# 可视化机会扫描（强制工作流）

这是 easy-html「图文并茂」的关键。**生成 HTML 骨架之前，必须先做一遍可视化扫描**——
把内容当成「要设计的素材」而非「要排版的文本」。不做这步 = 退化成原文搬运。

## 为什么强制
默认顺着原文结构走，会把表格画成表格、把数字埋在文字里、把流程写成列表，
结果「换了皮肤但形态没变」，和原文差不多。扫描的目的是**主动发现并转换**这些机会。

## 第一步：扫描内容，标记可视化机会

逐段过内容，按下表识别信号 → 决定转成什么组件（组件用法见 VIZ_COMPONENTS.md / CHARTS.md）：

| 内容信号 | 关键特征 | 转成 |
|---------|---------|------|
| 关键数字 | 出现绝对值/总量/同比（1.2亿、+25%、78%） | **大数字卡 KPI**（别埋在文字里）|
| 达成率/单一占比 | "完成 78%"、"占比 60%" | **进度条 / 进度环** |
| 排名/数值对比 | 多项带数值对比（各渠道占比、TopN） | **横向对比条**（替代表格）|
| 构成占比 | 总体拆成几部分（2-4 段） | **donut**（CSS 或 Chart.js）|
| 多点趋势 | 按时间/序列的多个数值 | **Chart.js 折线/面积图** |
| 多系列对比 | 多组×多类别数值 | **Chart.js 分组柱状** |
| 流程/步骤 | "第一步…第二步"、有序流程 | **流程箭头** |
| 时间/里程碑 | Q1/Q2、阶段推进 | **时间轴** |
| 两方对比 | A vs B、前端vs后端、能/不能 | **VS 双栏** |
| 关键词/标签 | 一堆并列短词、热词 | **标签云** |
| 重点/比喻/提示 | "一句话记住"、💡小贴士 | **信息高亮条** |
| 多维对照表 | 真正需要逐格对照的 N×M 矩阵 | **保留表格**（这是表格唯一合理场景）|

## 第二步：定信息层级（视觉权重）

不要所有模块一样大。排一下轻重：
- **重**：核心结论、关键 KPI → hero 大字 / 大数字卡 / 大图表
- **中**：分维度分析 → 卡片网格 / 对比条 / 中型图表
- **轻**：辅助说明、备注 → 小字、信息条、列表

## 第三步：生成骨架时套组件

- 命中信号的内容**优先用组件/图表**，不要默认表格/纯文字
- 表格只在「真·多维对照矩阵」时保留
- 每个 section 视情况配 1 个语义图标/emoji（统一风格，别滥用）
- 仍遵守 0 遗漏：转图形时原始数据/文字不能丢，必要时图形 + 简短文字说明并存

## 自检（生成后回看）
- [ ] 关键数字是否做成了大数字卡，而不是埋在句子里？
- [ ] 是否还有「本可以画成对比条/图表却用了表格」的地方？
- [ ] 流程/步骤是否用了流程箭头/时间轴而非纯列表？
- [ ] 整页是否有视觉轻重，而不是一堆等大卡片平铺？
- [ ] 至少用上了 2-3 类可视化组件（纯文档也应有 KPI/信息条/流程等）？

> 若一份内容扫描下来「确实没有任何可视化机会」（纯叙述文字），
> 也要用信息高亮条、引用块、图标、视觉层级把它做出阅读节奏，不能整页大白段落。
